# Implementation Plan

## P0：可复现、无破坏的原型

- [x] 创建项目、版本/约束文档。
- [x] 从公开 Papyrus API 核对自有飞船枚举、AI 开关、一次性寻路接口。
- [x] 编写只读 InventoryProbe 和**手动启用**的 AI/Path Probe 源码。
- [ ] 使用目标版 Creation Kit 编译脚本，生成可测试的实验 ESM/PEX。
- [ ] 验证自有船列表、Home Ship 和动态 Reference 身份。
- [ ] 以真实加载的非 Home Ship 测试无舰长 EnableAI。
- [ ] 在 B/C 两艘自建船上测试一次性 PathToReference。
- [ ] 在 CK 实现持续 Follow AI Package，验证 C 以 B 为目标、A 自由离开。
- [ ] 检查脚本原型在重命名/Ship Builder/出售后表现。

## P1：舰船实体化与回收

- [ ] 找出从玩家已有船列表安全部署活动非 Home Ship 的方法。
- [ ] 证明不用复制船体、不改变原拥有关系、不影响 Home Ship。
- [ ] 明确非加载场景、对接及回收的状态边界。
- [ ] 每步错误均可停止并回滚，不会吞船。

## P2：旗舰/护航舰指挥

- [ ] 建立玩家船、旗舰、护航舰三角色互斥注册表。
- [ ] 护航舰可为 0，数量按真实自有船动态管理。
- [ ] 旗舰固定为 Follow 目标；启用 AI + Escort/Wait Package。
- [ ] 无舰长时不能生成 NPC；若原生无法运行，评估 SFSE 原生控制器。
- [ ] 已有同伴舰长至多分配一艘，解任可逆。

## P3：持久化、恢复与安全性

- [ ] 真实引用身份和船体生命周期检测，避开船名与数组索引。
- [ ] 保存、读档恢复；保证幂等，不重复生成实体。
- [ ] 玩家改装、改名、切换 Home Ship、出售、DLC 加载压力测试。
- [ ] 对需要的 SFSE DLL 固定运行时版本，加入安全降级和错误日志。

## M0 完成定义

必须拥有经过 Starfield 1.16.244 实机验证的 ESM/PEX（必要时 DLL），玩家能选择自建旗舰、0..N 艘自建护航舰，并驾驶独立个人飞船离开；无舰长不凭空造人；舰队能在相同活动太空场景中稳定保持旗舰为跟随目标；保存/退出/读档不破坏船体身份。缺任何一项，仍属实验版本。

## 后续 M1+

舰队 UI、跨星系部署/召回、持久远征、维修/后勤、大型母舰内部功能等后续推进，不挤占 M0 验收。
